# BSFM Research Observatory — web architecture

Date: 2026-09-05
Status: final implementation batch

## Purpose

The public web surface is part of the scientific audit trail, not a marketing dashboard. It must make uncertainty, blocked gates and negative evidence at least as visible as a prospective forecast.

## Pages

- `site/index.html` — research overview, frozen F-002, current generated gate state, study design and links to deeper audit surfaces.
- `site/validation.html` — historical-case, exposure, PIT, calibration, paired-baseline and promotion gates; preregistered walk-forward design.
- `site/methodology.html` — immutable forecast→outcome→score protocol, target semantics, estimator/null model and fail-closed rules.
- `site/provenance.html` — generated source inventory, evidence roles, PIT semantics, census/exposure integrity rules.
- `site/styles.css` — shared responsive observatory design system.

## Generated public state

`AGGIORNA` writes and commits:

- `site/data/status.json` — source/registry/run state generated by the pipeline;
- `site/data/final-readiness.json` — machine-readable scientific readiness derived from the foundation and lifecycle audits;
- `site/data/refinements.json` — append-only prospective refinement surface.

The web pages read these JSON files with `cache: no-store`. They do not recompute scientific gates in JavaScript. Presentation reflects the Python audit result.

## Automatic publication

There remains exactly one workflow: `AGGIORNA`.

In the same integrated run it:
1. executes pre-refresh tests and integrity checks;
2. refreshes official source manifests and NTSB normalization;
3. executes post-refresh tests and scientific audits;
4. writes `final-readiness.json`;
5. commits changed generated research state;
6. configures/enables GitHub Pages;
7. uploads `site/` as the Pages artifact;
8. deploys it to the `github-pages` environment.

No second Pages workflow is introduced. Therefore one successful AGGIORNA updates both the auditable repository state and the public observatory.

## Publication safety invariants

- Software PASS is never rendered as scientific validation.
- `BLOCKED` remains visible for unknown empirical evidence.
- Absolute accident probabilities remain OFF until promotion readiness is real.
- F-002 is labelled experimental and immutable.
- The site explicitly states that BSFM is not an operational safety tool and does not assess individual flights, aircraft, airlines, routes or people.
- Global traffic context is not rendered as Boeing-family exposure.
- Later refinements remain separate from the original F-002 score.

## Verification

`tests/test_site.py` protects the page inventory, fail-closed public seed, research disclaimer, generated-state bindings, single-workflow rule and Pages deployment steps. The final AGGIORNA run is the integrated runtime verification of this publication chain.
